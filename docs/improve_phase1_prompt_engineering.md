# Phase 1: Prompt 工程重构

## 改进的目的

当前 `PLANNER_AGENT_PROMPT`（`backend/app/agents/prompts.py`）仅 22 行，只给出了 JSON 输出格式的结构性指令，完全没有：

- 对景点多样性的约束
- 对描述质量的明确标准
- 天气与景点类型的关联逻辑
- 禁止出现的模板套话

这直接导致 LLM 生成的行程"没有实际参考价值"——景点描述泛泛、每日建议雷同、`overall_suggestions` 是千篇一律的模板文本。**Prompt 重构是投入产出比最高的改进**，不改任何架构就能立即提升输出质量。

## 改进的内容

### 1. 角色定位升级

从"你是一个专业的旅行规划师"升级为"你是一位经验丰富的当地导游"，要求给出只有本地人才知道的实用信息。

### 2. 多样性硬约束

```
- 每天同类景点不超过 2 个
- 整个行程至少覆盖 min(天数 × 2, 5) 个不同景点类别
- 每天至少安排一个与前一天不同风格的景点
- 如有用户历史数据，每天至少包含一个用户未曾去过的景点
```

### 3. 描述质量量化标准

- 每个 `attraction.description` ≥ 80 字，必须包含：
  - 该景点最值得看的具体内容（名称要具体，如"九龙壁"而非"建筑"）
  - 最佳游览时间段（如"建议上午 9:00 前到达，避开旅行团"）
  - 一个实用 tips（如排队时长、是否需要预约、拍照最佳位置）
- 每日 `description` 必须包含：
  - 为什么这些景点搭配在一起（逻辑性）
  - 景点间的预估交通时间
  - 当日行程的节奏说明（紧凑 / 轻松）
- `overall_suggestions` ≥ 5 条，每条必须有具体内容，涵盖：
  - 穿衣建议（根据实际天气）
  - 必吃菜品（具体菜名，非"当地美食"）
  - 交通技巧（具体路线或方式）
  - 避坑提醒
  - 隐藏玩法

### 4. 禁止模式（黑名单）

明确列出禁止出现的模板文本：

```
禁止以下表述：
- "建议每天预留30-60分钟机动时间"
- "根据XX偏好搜索得到的目的地"
- "适合XX类型游客的景点"
- "祝您旅途愉快，玩得开心"
- "请注意安全，保管好随身物品"
```

### 5. 天气感知规则

```
- 晴天（晴/多云）→ 优先安排户外景点
- 雨天（小雨/中雨/大雨）→ 优先安排室内景点（博物馆、美术馆、购物中心）
- 高温天（>35°C）→ 户外景点安排在上午 10:00 前或下午 16:00 后
- 低温天（<5°C）→ 减少长时间户外停留，增加室内休憩点
```

### 6. 预算分配

```
- 不要每天平均分配预算
- 热门大景点门票可集中在 1-2 天
- 餐饮预算应随行程节奏变化（紧凑日简单吃，轻松日可推荐好的餐厅）
```

### 7. Few-shot 示例

在 prompt 末尾附一个高质量的 2 日北京行程 JSON 片段作为示例，展示"好的输出"长什么样。

## 改进的方法

### 修改文件

`backend/app/agents/prompts.py` —— 重写 `PLANNER_AGENT_PROMPT` 变量

### 实施步骤

1. 在 `prompts.py` 中定义新的 `PLANNER_AGENT_PROMPT`，包含上述所有内容
2. 保留旧的 prompt 作为 `PLANNER_AGENT_PROMPT_LEGACY`（方便对比和回退）
3. 在 `backend/app/config.py` 中添加配置开关：
   ```python
   use_enhanced_prompt: bool = True  # 可通过 USE_ENHANCED_PROMPT 环境变量控制
   ```
4. 在 `trip_planner.py` 的 `PlannerAgent.run()` 中根据配置选择 prompt

### 验证方式

1. 发起"北京 3 天 历史文化"请求
2. 检查：
   - [ ] 每个景点描述 ≥ 80 字且内容具体
   - [ ] `overall_suggestions` 包含 5 条以上城市特定的实用建议
   - [ ] 无禁止的模板套话
   - [ ] 天气与景点类型匹配（雨天的景点多为室内）
   - [ ] 每日 description 说明了景点搭配逻辑

### 影响范围

- 仅修改 1 个文件
- 无架构变更
- 零风险，可随时回退
- 立即生效，无需前端配合
